# 个人系统容器应用设计

日期：2026-06-10

## 目标

设计一个只服务单个用户的个人系统容器应用。第一版不是通用效率软件，而是个人系统的宿主应用，首发只内置一个模块：时间投入模块。

该应用的核心不是任务管理、提醒或自动判断，而是把个人规则固化成低摩擦的交互。

## 产品定位

- 这是一个个人系统容器，不是单一功能计时器。
- 第一版采用“薄容器 + 强模块”。
- 各模块彼此弱耦合，不要求共享统一业务模型。
- 当前唯一正式模块为“时间投入模块”。
- 未来可增加压力管理、目标清晰化等模块，但第一版不为它们做复杂联动。

## 长期结构

### 容器职责

- 提供首页和模块入口。
- 提供统一设置入口。
- 提供统一快捷键注册能力。
- 提供统一视觉和交互风格。

### 模块职责

- 每个模块独立定义自己的规则、数据和交互。
- 模块之间默认不强依赖共享数据。
- 模块可以并列存在于同一个应用内，但不强制统一工作流。

## 模块一：时间投入模块

### 问题定义

该模块解决的第一优先问题是“启动困难”。

因此，第一版首先是一个零阻力开工开关，而不是记录器、任务器或番茄钟。记录只是结果，开始动作必须足够轻。

### 核心原则

- 开始时不能要求思考。
- 开始时不能要求输入。
- 开始时不能要求分类。
- 开始时不能要求选择任务。
- 所有认知负担后移到结束阶段。
- 系统不定义什么叫生产或消费，定义权完全交给用户。
- 系统不替用户判断，只在正确时机要求用户裁决。

### 模块规则

该模块固化一条核心规则：

> 不能命名的生产，不算生产。

这条规则的含义是：

- 一段时间结束后，如果用户判定其为“生产”，则必须立即填写该段时间的产出内容。
- 如果用户无法立刻回答这段时间产出了什么，则该段时间自动降级为“消费”。
- 如果用户判定其为“消费”，则无需填写内容。

### 完整交互流

#### 开始

- 用户按一次全局快捷键。
- 系统立即开始一段新的时间投入 session。
- 不弹窗，不输入，不选择，不确认。
- 菜单栏状态点切换为进行中状态。

#### 进行中

- 系统静默计时。
- 存在一个默认参考时长。
- 默认参考时长到达时不提醒、不打断、不震动。
- 超过参考时长后继续静默累计。

#### 结束

- 用户主动结束当前 session。
- 系统立即弹出一个极小裁决面板。
- 面板只先问一个问题：
  - 这段时间是“生产”还是“消费”？

#### 若选择消费

- 直接记录完成。
- 不追问内容。
- 随后显示今日累计：
  - 今日生产 X
  - 今日消费 Y

#### 若选择生产

- 用户必须立即填写一条产出描述。
- 该描述必须在结束时立刻填写，不允许延期补充。
- 若用户答不出来，则该 session 自动记为消费。
- 记录完成后显示今日累计：
  - 今日生产 X
  - 今日消费 Y

#### 记录完成

- 返回静默状态。
- 不显示庆祝、鼓励或成就型反馈。
- 默认把用户放回当天总账视角。

## 首页设计

首页是容器页，不是重型仪表盘。

### 首页目标

- 让我一眼看到当前有哪些模块。
- 让我快速进入当前最常用的模块。

### 首页内容

- 当前模块列表。
- 每个模块的一句话状态。
- 模块入口卡片。

### 第一版首页建议

- 时间投入：显示今日生产 / 今日消费累计
- 压力管理：尚未启用
- 目标清晰化：尚未启用

### 首页明确不做

- 不堆大量图表
- 不展示长日志流
- 不承载复杂复盘内容
- 不做模块间联动解释

首页的角色只是容器入口，不是总控大盘。

## 时间投入模块最小数据模型

### 核心单位

一条 session 就代表一段主动投入。

### 字段

- `id`
  - 唯一标识
- `start_at`
  - 开始时间
- `end_at`
  - 结束时间
- `duration_seconds`
  - 持续时长
- `classification`
  - `production` 或 `consumption`
- `production_note`
  - 仅当 `classification = production` 时必填
- `ended_by_user`
  - 是否由用户主动结束
- `reference_duration_seconds`
  - 该次 session 使用的默认参考时长

### 第一版不需要的字段

- 项目 ID
- 目标 ID
- 标签系统
- 情绪分值
- 能量分值
- 自动分类结果
- 消费备注
- 复杂统计缓存对象

### 今日累计

“今日生产”与“今日消费”通过当天 session 聚合实时计算，不单独设计日报主对象。

## 第一版重点观察的行为信号

第一版不是为了做报表，而是为了看见自己。

重点观察：

- 启动频率
- 启动后完整结束的比例
- 生产 / 消费比例
- 生产被降级为消费的频率
- 单段时长分布
- 当天未收尾 session 的数量

这些信号的意义是为后续设计提供证据，而不是做效率 KPI。

## 第一版边界

### 坚决不做

- 不做任务管理
- 不做番茄钟提醒
- 不做自动生产力判断
- 不做复杂统计面板
- 不做模块联动
- 不做云同步或多人协作
- 不做过多输入字段
- 不做鼓励式反馈

### 第一版只验证三件事

- 用户能不能更容易开始
- 用户会不会诚实地结束并裁决
- “不能命名的生产，不算生产” 这条规则是否有效

## 后续扩展原则

- 新模块应独立成立，不依赖时间投入模块的数据模型。
- 容器只提供统一入口和风格，不强制共享业务语义。
- 未来可以加入压力管理、目标清晰化等模块，但不应反向污染时间投入模块的极简性。

## 结论

第一版本质上是一个个人系统容器应用，其中首发模块是一个“状态开关型”的时间投入模块。

它的价值不在于记录时间本身，而在于把一条个人规则固化成低摩擦的行为闭环：

开始时零阻力，结束时必须裁决；若称其为生产，则必须说出产出内容，否则降级为消费。
